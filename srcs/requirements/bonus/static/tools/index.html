About Inception

Inception is a project from 42 focused on Docker, containers, networking, volumes, security and system administration. The objective is to build a complete infrastructure composed of several independent services that work together through Docker Compose.

Docker is a platform used to build and run applications inside isolated environments called containers. Instead of installing every application and dependency directly on the host system, Docker allows each application to run inside its own controlled environment.

A container is an isolated environment created from a Docker image. It contains the files, libraries, configuration and processes required by an application. Containers are lightweight because they share the kernel of the host operating system instead of running a complete operating system like a traditional virtual machine.

A Docker image and a container are also different concepts. An image is the template used to create a container. The image is built from instructions written in a Dockerfile. A container is the running instance created from that image.

In Docker Compose, a service describes how a container should be created and executed. For example, MariaDB is a service in the Compose file, and Docker uses that service definition to create the MariaDB container. Inside that container, the MariaDB server process is executed.

Containers are normally temporary. They can be stopped, deleted and recreated at any time. This creates a problem for important data such as databases and website files. Docker volumes solve this problem by storing data independently from the lifecycle of the container.

In this project, MariaDB uses a persistent volume to store the database files, while WordPress uses another persistent volume to store the website files. Even if the containers are destroyed and rebuilt, the information stored inside these volumes remains available.

Docker networks allow containers to communicate with each other without exposing every service directly to the host machine. Containers can communicate using their service names as hostnames. For example, WordPress can connect to MariaDB using the name "mariadb", and NGINX can communicate with WordPress using the name "wordpress".

NGINX is the main external entry point of the infrastructure. It receives HTTPS connections from the client and uses TLS to protect the communication. PHP requests are forwarded to the WordPress container, where PHP-FPM processes them.

WordPress uses MariaDB to store information such as users, posts, comments and configuration. Redis can be used as a cache to reduce repeated database operations and improve performance. Adminer provides a graphical web interface for inspecting and managing the MariaDB database, while FTP provides access to the files stored inside the WordPress volume.

Docker Compose is important because it allows the entire infrastructure to be described in a single configuration file. It defines services, networks, volumes, ports, secrets, dependencies and build instructions. With one command, Docker Compose can create and start all the required containers.

Inception is important because it introduces concepts that are widely used in modern infrastructure and DevOps environments. The project demonstrates how applications can be separated into independent services, how they communicate securely, how data can remain persistent and how an entire infrastructure can be reproduced automatically from configuration files.
